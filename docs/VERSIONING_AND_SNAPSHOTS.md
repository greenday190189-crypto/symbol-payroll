# Версии правил и снимки расчётов

## Правила

- Новая редакция правила добавляется отдельной записью с увеличенным номером версии.
- Существующие правила запрещено обновлять и удалять на уровне SQLite-триггеров.
- Для одной области действия применяется наиболее специфичное правило; при пересечении периодов одной области действия выбирается правило с наиболее поздней датой начала, затем с большей версией.
- При совпадении приоритета, даты начала и версии система сообщает о неоднозначности.

## Расчётный период

Жизненный цикл: `draft → calculated → approved → closed`.

- Для утверждения требуется хотя бы один сохранённый снимок.
- Снимок хранит сериализованные расчётные данные и SHA-256 отпечаток списка применённых версий правил.
- После утверждения снимки нельзя изменять, удалять или добавлять.
- Утверждённый период нельзя вернуть в черновик через штатный сервисный метод.

## Текущие ограничения

- Валидация полного состава сотрудников перед утверждением пока не реализована.
- Создание снимков пока вызывается сервисным кодом, а не графическим интерфейсом.
- Снимок должен передаваться уже с расшифровкой начислений; расчётный сервис ещё не объединён с репозиторием.
- SHA-256 отпечаток подтверждает список версий правил, но не заменяет цифровую подпись и не защищает от прямого вмешательства в файл БД вне приложения.
