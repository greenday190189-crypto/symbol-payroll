# Зафиксированные решения

## Продукт

- Целевая платформа: Windows 10/11, локальная установка на одном рабочем месте бухгалтера.
- Предварительный стек: Python 3.11+, PySide6, SQLite, openpyxl, PyInstaller.
- В исходной книге 9 листов: Сигаево, Дачная, Дубровская, Калинина, Путейская, Электрозаводская, Азина, Элеконд, увольнение.
- Все листы являются актуальными образцами процессов, но значения в них пользователь назвал примерными. Исторические значения не переносить как действующие тарифы.

## Правила оплаты

- Схема оплаты индивидуальна для каждого сотрудника.
- Требуется гибкая иерархия настроек: организация → магазин → должность → сотрудник → индивидуальное исключение на период.
- Более специфичное подтверждённое правило переопределяет общее. Источник и версия применённого правила должны быть видны в расшифровке.
- Произвольное исполнение Python из пользовательского интерфейса запрещено; пользовательские формулы реализуются безопасным ограниченным языком выражений.

## Премии

Отдельно настраиваются план, процент/ставка, участники фонда, получатели, база распределения и способ распределения. Эти параметры нельзя сводить к одной фиксированной формуле.

## НДФЛ и обязательные выплаты

- Пользователь хочет учитывать НДФЛ в приложении вариативно.
- Нужны режимы: автоматический, ручной, импортированный, отключённый.
- Оклад может быть задан как gross (до НДФЛ) или net (на руки). Для проекта это пока не подтверждено. Поле должно поддерживать оба значения; unconfirmed блокирует утверждение расчёта, если от него зависит НДФЛ.
- Автоматический НДФЛ нельзя реализовывать на фиксированной ставке без налогового профиля, налоговой базы, необходимых накопительных данных и версионированных правил, соответствующих периоду расчёта.
- НДФЛ, больничные, отпускные и прочие обязательные выплаты не считать одной общей категорией. Их методики требуют отдельного подтверждения.

## Надёжность

- Утверждённый расчёт хранит неизменяемый снимок исходных данных и версий правил.
- Неизвестные параметры не подменяются предположениями.
- Нулевые знаменатели, отсутствующие смены и некорректные ссылки должны приводить к диагностике и блокировке соответствующей операции, а не к тихому нулевому результату.
