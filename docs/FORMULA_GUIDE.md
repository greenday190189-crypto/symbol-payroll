# Формулы расчёта заработной платы

Этот справочник описывает язык формул, который поддерживается редактором правил Symbol Payroll.

## Главное правило

Формула — это арифметическое выражение, которое возвращает сумму в рублях. В формуле используются только доступные числовые переменные, числа, скобки и арифметические операции. Это **не Excel** и не Python.

## Разрешённый синтаксис

| Запись | Значение | Пример |
|---|---|---|
| `+` | сложение | `salary + fixed_adjustments` |
| `-` | вычитание | `sales - plan` |
| `*` | умножение | `sales * 0.03` |
| `/` | деление | `salary / 22` |
| `(...)` | порядок вычислений | `(salary / 22) * shifts` |
| `-число` | отрицательное значение | `-100` |

Порядок действий стандартный: сначала скобки, затем умножение/деление, затем сложение/вычитание.

Не поддерживаются: знак процента `%`, степени, функции `max()`/`min()`, ссылки на ячейки Excel, текстовые значения, условия `IF`, циклы, произвольный Python-код. Деление на ноль и неизвестные переменные приводят к ошибке расчёта.

## Переменные

| Переменная | Что означает |
|---|---|
| `salary` | Оклад, подтверждённый как сумма **до удержания НДФЛ (gross)**. При другой или неизвестной базе равен нулю в контексте формулы. |
| `salary_net` | Оклад, подтверждённый как сумма **на руки (net)**. Не является gross-начислением. |
| `shifts` | Фактически отработанные смены за период. |
| `hours` | Фактически отработанные часы за период. |
| `sales` | Фактические продажи/выручка сотрудника за период, руб. |
| `plan` | План продаж сотрудника за период, руб. |
| `advances` | Сумма выплаченных авансов, руб. |
| `deductions` | Прочие удержания, руб. |
| `manual_tax` | НДФЛ, введённый вручную или полученный из внешнего расчёта, руб. |
| `fixed_adjustments` | Ручные фиксированные корректировки, руб. |

Дополнительные переменные можно задать в таблице расчёта в колонке «Доп. параметры (JSON)». Например:

```json
{
  "commission_rate": "0.03",
  "night_hours": "12"
}
```

В формуле имя используется без кавычек: `sales * commission_rate`. Значения дополнительных параметров должны быть числами.

## Примеры формул

| Задача | Формула | Что получится |
|---|---|---|
| Оклад пропорционально сменам при делителе 22 | `salary / 22 * shifts` | Доля gross-оклада за фактически отработанные смены |
| Оплата по часам при условном делителе 176 | `salary / 176 * hours` | Доля gross-оклада за фактически отработанные часы |
| Комиссия 3% от продаж | `sales * 0.03` | 3% от фактических продаж |
| Комиссия по индивидуальной ставке | `sales * commission_rate` | Продажи, умноженные на параметр сотрудника |
| Доплата за каждую смену 500 руб. | `shifts * 500` | Количество смен, умноженное на 500 руб. |
| Фиксированная доплата плюс оплата смен | `fixed_adjustments + salary / 22 * shifts` | Сумма двух частей |

Число `0.03` означает 3%, `0.1` — 10%. Знак `%` писать нельзя.

**Важно:** примеры с делителями 22 или 176 — только математические образцы. Делитель, способ оплаты и применимость формулы должны быть подтверждены для конкретного сотрудника/магазина. Приложение не выбирает правильный делитель автоматически.

## Категория правила

Категория определяет, как результат попадёт в расчёт:

- `earning` — начисление, увеличивает начисленную сумму;
- `bonus` — премия, также относится к начислениям;
- `net_salary` — сумма на руки; не должна ошибочно прибавляться к gross;
- `deduction` — удержание;
- `unclassified` — сумма без подтверждённой классификации; требует проверки.

Название правила отображается в расшифровке расчёта. Код должен быть коротким уникальным идентификатором, например `shift_pay` или `sales_bonus`.

## Область действия правила

Правило может действовать для всей организации, магазина, должности, сотрудника или как исключение на конкретный период. Более конкретные настройки переопределяют общие в соответствии с приоритетом уровней. Для области «Вся организация» используйте идентификатор `*`; для остальных уровней указывается соответствующий ID или точное название должности.

## Проверка перед использованием

1. Создайте правило с понятным названием и категорией.
2. Проверьте формулу на нескольких тестовых наборах: ноль смен, полный месяц, неполный месяц, нулевые продажи.
3. Сверьте результат вручную с утверждённым способом расчёта.
4. Только после сверки используйте правило в рабочем периоде.
5. Не утверждайте ведомость, если база оклада gross/net или методика расчёта не подтверждены.

Формулы из Excel не исполняются автоматически при импорте. Импорт переносит значения ячеек, а формулы приложения настраиваются отдельно в редакторе правил.
